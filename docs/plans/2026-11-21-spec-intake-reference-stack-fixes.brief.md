## 🟢 Fix now (safe)
Mechanical, contained, one clearly-correct fix each. /esq:fix applies these.
- An existing esq project with no `docs/DECISIONS.md` is treated as a fresh import, so `/esq:advance` refuses to run. Who hits it: a user who works through `/esq:backlog`, `/esq:roadmap` and `/esq:work` (esq-format BACKLOG.md and ROADMAP.md) but has never had a decision recorded, and keeps 3 or more ordinary docs of 20 KB or more under `docs/` (api.md, deploy.md, guide.md). What goes wrong: `esq state` answers `intake.pending: true`, so every unscoped `/esq:advance` STOPs, `/esq:status` routes to `/esq:harvest` instead of the roadmap, and SessionStart says the docs are "not adopted". It stays that way until a DECISIONS.md exists. Reproduced in a scratch repo: `{"pending":true,"files":3,"kb":28,"reason":"3 foreign Markdown files (28 KB) and no esq registry"}`. The plan's premise ("every project that already runs esq has a registry") does not hold. — `plugin/lib/intake.mjs:126` — fix: in `scanDocs`, intake is not pending when any `ledgers` value is `esq`, not only `DECISIONS.md`. The `peek` (line 112) reads the first `peek` bytes of `BACKLOG.md` and `ROADMAP.md` the way it reads `DECISIONS.md`, and README's Hooks privacy bullet (`README.md:458`) names those two files. — verify: a new case in `tests/cli/intake.test.mjs` with an esq ROADMAP.md (`## Now`), an esq BACKLOG.md, no DECISIONS.md and 3 foreign docs of at least 20 KB, where `state().intake.pending` and `scanDocs(root, { peek: 4096 }).pending` are both false; then `./scripts/audit.sh`
- An intake that finds no settled decision cannot commit, and stays pending after it runs. Who hits it: a user whose imported specs record every decision as open, which is common for chat-written drafts that await confirmation. What goes wrong: § 5 chains `esq decisions add -` with an empty array, and the CLI refuses that with `no entry given`, so the `&&` chain stops before any `esq backlog add`. Even with step 2 skipped, step 4's `git add docs/DECISIONS.md docs/BACKLOG.md` fails on a pathspec that does not exist, and no DECISIONS.md means intake stays pending. — `plugin/skills/harvest/references/intake.md:65` and `:77` — fix: run step 2 only when at least one entry was settled or answered, and make step 4 stage only the ledgers this run wrote (`git add docs/BACKLOG.md`, plus `docs/DECISIONS.md` when step 2 ran). With the first fix above, the new esq BACKLOG.md then clears `pending`. — verify: `bash scripts/check-structure.sh`
- A chat-written decision table headed `| # | Decision | Status |` is taken for esq's registry. Who hits it: a user whose imported `docs/DECISIONS.md` uses a numbered Markdown table, a frequent shape for model-written registries. What goes wrong: `FORMAT_OWNED['DECISIONS.md']` matches any `| # |` header, so intake reports `registry: 'esq'`, `pending: false`, and the import is never adopted. A later `esq decisions add` (whose `tableAt(lines, '#')` finds that table) then writes esq rows into the user's foreign file instead of moving it to `DECISIONS.imported.md`. — `plugin/lib/intake.mjs:31` — fix: require esq's header, `/^\|\s*#\s*\|\s*Date\s*\|/m`, and for `BACKLOG.md` likewise `/^\|\s*ID\s*\|\s*Date\s*\|\s*Type\s*\|/m` (both are the leading columns of `DECISIONS_TEMPLATE` and `BACKLOG_TEMPLATE`). — verify: a case in `tests/cli/intake.test.mjs` where `docs/DECISIONS.md` is `| # | Decision | Status |` with padded foreign docs, expecting `registryCollision: true`, `pending: true`; then `./scripts/audit.sh`
