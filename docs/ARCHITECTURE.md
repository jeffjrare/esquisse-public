## Overview

esquisse is a Claude Code plugin named `esq`. It is made of three runtime parts under `plugin/` — twenty-one **skills** (Markdown prompts, the product), a dependency-free **CLI** (`esq`) that owns every structured operation the skills would otherwise do probabilistically, and four **hook handlers** over five events that guard the installed files, block a stop on a broken ledger, and record telemetry for subagent runs and for esq commands run in the main session — plus the Markdown **ledgers and projections** under `docs/` that the skills read and write — among them a **harness-evidence registry** (`docs/EVIDENCE.md`), the one ledger no command writes, recording which version of Claude Code each claim about the harness was measured on. Around the runtime sits a **guard suite** (`scripts/audit.sh` and its extracted checks) that verifies resolvable references, parsed formats and product behavior across the skill corpus — plus, beside it and never inside it, a **runtime-evidence runner** that bills real tokens to prove a scenario end to end. The repository is its own marketplace (`.claude-plugin/marketplace.json` → `./plugin`).

## Components

### `plugin/skills/<name>/SKILL.md` — the twenty-one commands, and the source of truth
**Owns:** every judgment — what to build, how to decompose it, what is material, what severity, what to ask the user and at what altitude. Announces its cost bound before its first tool call and concludes in three zones.
**Entered by:** `/esq:<name>` from the user; the seven orchestrator-invoked skills (`build`, `check`, `review`, `fix`, `work`, `plan`, and `roadmap` for its bare refresh only) also via the `Skill` tool from a subagent the unattended trio (`advance`, `autopilot`, `converge`) spawned.
**Depends on:** the CLI for anything with an exact answer (`esq state`, `esq next-phase [--context]`, `esq brief depth|plan|pending`, `esq review scope`, `esq backlog add|reserve-id|reserve-block|set-status`, `esq plan append-log`, `esq plan resolve-block`, `esq plan set-reviewed`, `esq plan abandon`, `esq branch check`, `esq projections`, `esq gate verify`, `esq merge land`, `esq validate`, `esq telemetry summary`); the ledgers in `docs/`; the README for mode and argument syntax (a `description:` only routes — D-description-routes-readme-explains).
**Good to know:**
- The frontmatter is a contract `scripts/check-plugin.sh` enforces: stable `name`, `model` + `effort`, `$ARGUMENTS` and `$0` consumed. There is no line cap and no skill count: a number in a guard is a number to renumber, and an entrypoint's length is a readability judgment rather than a defect a script recognizes. Fourteen skills carry `disable-model-invocation: true`; the seven above cannot (the flag blocks *every* Skill-tool call, including a delegated one) and carry the in-body **"No mandate, no run."** refusal instead (D-orchestrated-skills-guard-in-body). `build` alone is split into `references/` for progressive disclosure — the procedures an ordinary phase never reaches (the branch refusal, the `(manual)` probe and the paused-phase resolution that runs it, the blocked-phase resolution, the failure report) plus, since 2026-09-16, the bookkeeping procedures a phase reaches only when it owes work in them: `references/decisions-and-backlog.md` is loaded on three declared branches — candidates to file at step 2, a qualifying decision at step 6, the plan's last phase completing and owing its delivered rows an inspection — so a non-final phase with `"None."` candidates and no decision skips the bookkeeping instructions while still loading the reporting contract: the shared conclusion block moved with the reporting procedures into `references/reporting-and-stops.md`, which every reporting route reads. `check-structure.sh` resolves every `references/…` path a skill names; that a reached branch actually *carries* its load is `docs/AUDIT.md`'s reading pass (§ Rules).
- A paragraph two skills must carry identically is wrapped in `<!-- <family>:name:start/end -->` markers and registered in `scripts/check-sharedblocks.sh` (families `shared:` and `orch-shared:`); older families (`announce`, `announce-open`, `conclusion`, `decision-block`, `decision-ask`, `ask-altitude`, `id-allocation`, `brief-routing`) are hashed by their own numbered checks. Only text identical *by design* goes inside the markers.
- No skill forks (`context: fork`) — D-context-fork-only-after-proof. Pins are Opus by default and Sonnet on the five skills that let the CLI own the structure (`status backlog epic sweep worktree`) — D-opus-default-sonnet-only-mechanical. The three relay orchestrators pin nothing: they declare `model: inherit` and take the session's model (D-relay-inherits-the-session-model), because a typed pin is not observed to bite in a *running interactive* session. The `Agent` tool's explicit `model` field is the lever that does hold, and it is how an orchestrator on a cheaper model puts every worker on Opus. **Nothing asserts afterwards whether it did.** If the field is not honored the worker inherits the session's model, which the run reports in one line and never stops on — the post-spawn assertion and the evidence preflight that used to precede it both retired on 2026-09-22, because a measurement registry every project but this one lacks was refusing orchestration to projects that had done nothing wrong.

### `plugin/bin/esq` + `plugin/lib/` — the deterministic CLI
**Owns:** parsing Markdown tables and plan files, reserving a worktree's ID block and minting backlog IDs from it (`backlog reserve-block`, `reserve-id`), filing a row with its provenance in the `Source` cell (`backlog add`), flipping a status cell with the `--by` / `--reason` / `--resolution` it was closed on in the same write, appending a phase's execution-log entry and, for `/esq:fix`, the append-only proof block a recording item earned (`plan record-verification`, attributed by exact `(auto)`-step text identity and refusing everything else), the `validate` invariants (ID shape and uniqueness, closed status vocabulary, decision table ↔ detail parity, plan log consistency), the `state` snapshot `/esq:status` and `/esq:advance` read — including `idBlock` (`main` / `marker` / `missing`) and `inFlight`, the units living on unmerged branches with their plans and undisposed `Planned by` rows, a plan recorded abandoned left out — the plan a corrective brief corrects with the `range` and `finder` beside it (`brief plan`), the corrective generation a name sits at (`brief depth`), the scope a review reads (`review scope`: a plan path or a positional `<A>..<B>`/`<ref>`, answering a pinned `HEAD`, the mode, the delta base with its provenance, and the changed paths), the telemetry summary, the harness-evidence freshness verdict (`evidence`, reading `docs/EVIDENCE.md` against one bounded `claude --version`), and every durable fact a landing reads — projection freshness (`projections`), review coverage recorded and judged (`plan set-reviewed`, and the unit's `coverage` on `branch check`), the unit's completeness and obligations (`unit.incomplete`, `unit.abandoned` — a plan leaves the first only through `plan abandon` — `unit.open`, `unit.promised`, `unit.findings`) and whether it already `landed`, what verification git still proves across every plan of the unit (`gate verify --unit`), that `HEAD` is still the tree it proved (`branch check --at <head>`, verdict `moved`), and the merge itself (`merge land`). Returns JSON; a read whose audience is a person at a terminal and off which no skill routes — `telemetry summary` — prints a report by default and the same numbers behind `--json`. The exception is that criterion, not a list.
**Owns deliberately not:** any choice — approach, severity, materiality, phase boundaries (D-cli-owns-structure-model-owns-judgment).
**Entered by:** skills' Bash (it is on `PATH` once the plugin loads); the Stop hook imports `validate` directly; `tests/cli` imports the functions.
**Depends on:** Node built-ins only; `git` for root/branch/dirty. A `NODE_ENV=test` + `ESQ_TEST_GIT_ROOT` seam replaces git in tests. The only imports from `plugin/scripts` are `hook-io.mjs`'s pure predicates — `telemetryOptedOut` and `carriesWholeRunUsage` (built-ins only, no cycle — D-summary-opt-out-note-via-hook-io, D-writer-reader-predicate-lives-in-hook-io).
**Good to know:** every write goes through `atomicWrite` (temp file, same mode, rename). `evidence` is arithmetic on recorded cells and never a measurement: it compares each claim's single `current` row against the installed version and answers `fresh` / `stale` / `never-measured` / `unknown`, always exits 0, rides inside `state` as `evidence` so `/esq:status` buys no second call, and and reports them. **It authorizes nothing.** Until 2026-09-22 it also answered a `relay` verdict the three orchestrators consulted before their first spawn, so a project with no registry — which is every project but this one — was refused orchestration from any model but Opus; that field, the preflight and `esq state`'s copy of the report all went together, and `esq evidence` is now a maintainer's read of a maintainer's ledger. `state` never exits nonzero on a malformed ledger — a plan the parser rejects rides in `plans[]` as `state: "invalid"` with the same `error` message `validate` reports, a backlog table it cannot shape rides as `backlog.error` with no `counts`/`rows`, and every healthy fact stays beside them; `validate` is the command that exits on a fault, and `/esq:status` treats the degraded JSON as its primary path, never a reason to fall back to prose. `telemetry summary` pools every `~/.claude/plugins/data/esq-*` directory (marketplace and `--plugin-dir` installs) unless an explicit file argument un-pools it — `CLAUDE_PLUGIN_DATA` stays a harness→hook channel the CLI never reads (an export blinded the model assertion, B-048; the summary notes an exported-and-ignored var) — and names the B-036 blind spot (interrupted subagents leave no row) in its output. The reader owns every dedupe rule — one record per `agentId` (the one that `carriesWholeRunUsage`: a `SubagentStop` with a `runUsage` object; a fallback row it replaced counts as a `supersededFallback`, a same-quality repeat as a `duplicate`), the last row per `(sessionId, segment)` for direct rows — names every token-less run (`fallbackOnly` / `noUsage` / `zeroUsage`) and lets none of them into a token median (a zero-sum `runUsage` is a measurement failure, never a sample), and stamps every group with fewer than `MIN_SAMPLE_RUNS = 5` token-bearing runs `provisional`; the threshold is a constant, never a flag (D-telemetry-sample-threshold-five-runs). Every group carries four axes, not three: tokens, tool calls, **round trips** (`apiRequests` — the count whose product with the context size at each one is what a run actually costs, B-070) and duration, each a sum and a median over the runs that carry it. The calls-per-round-trip ratio is not a fourth median: it is summed over the `paired` sub-population of runs carrying *both* counts, so a row predating `apiRequests` cannot put its tool calls over someone else's trips, and it prints to two decimals rather than through `humanCount` because the figures being compared sit between 1.0 and 1.3 (D-calls-per-turn-over-a-paired-population, D-ratio-sealed-with-its-population). A group with no paired run prints `—`, never a ratio over half a population. Anything reading the raw files goes through `summarizeTelemetry` or reimplements those rules. The summary's `by command × model` table answers, after the fact and gating nothing, whether spawns got the model they asked for — the label's `requestedModel` against the run's `models[]`, through one family rule (`spawnModelVerdict`). A group's verdict is worst-of over what its runs asked (D-command-model-group-verdict-worst-of-asked); the per-run split lives in the `spawn model:` header, never in the row. **No command waits on that answer**: `telemetry assert-model`, which polled for the asynchronous writer and exited 1 on a mismatch so an orchestrator would halt, was removed with the preflight above. `apply route <do-string>…` is the read-only answer an orchestrator buys before it buys an agent: per chosen option, `route` is `apply` (a subagent may run it), `relay` (the named skill's own frontmatter carries `disable-model-invocation: true`, read from `plugin/skills/<name>/SKILL.md` resolved relative to `cli.mjs` so one path serves the checkout and the installed plugin) or `stop` (unknown or mixed — one `/esq:<skill>` token at the start with no chaining is the whole recognizer, and everything it cannot place fails closed to `stop`, never to a spawn); for a relayed one it also reports `applied`, `true`/`false` only where the invocation's arguments name a `B-NNN` and a status from `STATUSES` and `docs/BACKLOG.md` settles it, and `null` — with `confirm` saying why — everywhere else (D-executability-is-read-from-the-skill). `brief plan <fixes-brief>` is the read-only resolution `/esq:fix` routes on, and the only place it gets a target. From the brief's own `Source:` it answers `plan` — the stem, resolved by slug among the brief's siblings — or, when that line names a commit range instead, `range` with `plan: null`, which is how a review of a change with no plan file stays workable end to end. Either way it answers `finder` (`check` / `review` / `null`), which is what stops `/esq:converge` recording review coverage after a run that only applied a check's findings. It refuses — naming both slugs, or every candidate — when the filename and the `Source:` disagree or when more than one plan matches, rather than ranking the two or taking the first sorted hit (D-a-brief-identity-is-validated-never-ranked); only a `Source:` that itself names a range makes a brief plan-less, so none of those refusals is relaxed by that case. `brief depth <plan-or-fixes-brief>` is the separate chain question — the corrective generation a name already sits at, the `CORRECTIVE_DEPTH_BOUND = 2` it is measured against, and `open`/`exhausted` for the round it would open — from the name alone, over the same `-fixes(-<n>)` walk that yields the stem `esq branch check` compares ownership on, so no skill re-derives the bound from a filename (D-corrective-generations-bounded-at-two); a uniquifier is the same generation, and `exhausted` is an answer at exit 0, never a refusal. **The round a path opens is `depth` for a `.brief.md` and `depth + 1` for a plan** — a brief's own name already carries the `-fixes` of the round it opens, and every skill calls the verb with the brief path it is about to write; counting the plan's rule over both refused the *second* generation as though it were the third, and shipped green because the recorded verification and the suite's boundary case both walked plan paths.

### `plugin/hooks/hooks.json` + `plugin/scripts/*.mjs` — four bounded handlers, five events
**Owns:** `PreToolUse` → `protect-installed.mjs` denies Edit/Write/mutating-Bash on the installed plugin cache (not on a `--plugin-dir` source tree inside the project). `Stop` → `validate-stop.mjs` runs `esq validate` and blocks **once** (`stop_hook_active` short-circuits), only when the findings touch *uncommitted* structured state — defects committed by earlier sessions never hold this one hostage. `PostToolUse(Agent)` + `SubagentStop` → `record-agent-telemetry.mjs`. `Stop` (async) + `SessionEnd` → `record-session-telemetry.mjs`, the direct-path writer: the bytes the main-session transcript gained since the last Stop, per-session cursor sidecar, one cumulative content-free row per open esq segment in `telemetry/session-runs.jsonl`.
**Depends on:** `CLAUDE_PLUGIN_ROOT` / `CLAUDE_PROJECT_DIR` / `CLAUDE_PLUGIN_DATA` from the harness; each handler exports a pure function and only runs under `isMain`, which is what `tests/hooks` exercises.
**Good to know:** telemetry is *numbers only* — ids, model, token counts, durations, tool counts; never a prompt, a description, or a response (D-hook-telemetry-stops-at-observable-usage). `SubagentStop` is the primary writer, summing usage from the agent transcript; `PostToolUse` is the fallback plus the `AgentLabel` row, which carries a closed set of validated fields — the `esq:<command>` slug, the spawn's `requestedModel`, the declared `plan:<slug>` when one was marked, and the `repoKey` every row gets (each against its own pattern; a value outside it is omitted, never stored raw). Two handlers racing for one run are serialized by an exclusive-create claim file per `agentId`, never a scan-then-append (D-telemetry-dedupe-by-claim-file), and under it *the most complete record wins*: a whole-run `SubagentStop` row is appended over a fallback row that landed first (bounded claim retry on `EEXIST`), a fallback never overwrites and skips when any record exists — so one run may leave two rows of different sources and the file stays append-only, while two rows of the *same* source still mean the claim path was bypassed (D-whole-run-record-supersedes-fallback). Writer and reader share that one predicate, `carriesWholeRunUsage` in `hook-io.mjs` — the same file as the opt-out, for the same reason: a rule both sides apply has one definition. `ESQ_TELEMETRY=0` / `DO_NOT_TRACK=1` (`telemetryOptedOut` in `hook-io.mjs`) switches every telemetry writer off before any read, and `esq telemetry summary` imports the same predicate to say so; the validator and the protect hook never consult it. The session writer's bound is a property, not a sentence: a per-session sidecar (`telemetry/.cursor-<sessionId>.json`) carries the byte offset past the last complete line plus the open segment's running totals, so each Stop reads only what the transcript gained; only lines that can carry a marker (a user line with `<command-name>`, an assistant line with a `Skill` tool_use) are parsed for one, the shared reducer runs with `readText: false`, and a segment is attributed to its most recent opener (`via: typed | skill-tool`) until the next typed command or session end. One exclusive-create claim per session (stale after 30 s) serializes the async Stop against SessionEnd, which waits bounded for it because it is the last chance to close the segment and remove the sidecar (D-direct-session-telemetry-stop-cursor, D-session-row-per-touched-segment). Semantic notifications stay in the skills as explicit `PushNotification` calls; there is no generic Stop/Notification hook (D-semantic-notifications-stay-in-skills).

### `scripts/audit.sh` + the checks it runs — the guard suite

**One dispatch.** Every check goes through `run "<label>" <cmd…>`, which executes it, prints its summary or its whole output, and folds its exit code into the tally. **Only 0 passes.** 1 is findings; 2 means the check could not read its own inputs and is a failure like any other non-zero code, because the flags have already decided which checks are selected and a selected check that cannot answer has not answered. A verdict a check withholds on purpose — `check-release-version.sh`'s drift half off `main` — exits 0 and says so, rather than borrowing the code that means "unusable input". There is no second dispatch shape to keep in sync — which is why nothing here needs a second check to prove it handles return codes, and why two checks that did exactly that retired with the shape they analysed (2026-09-22).

**What earns a check.** Two kinds, and only two: *a reference that must resolve* (`check-structure.sh` — a section cross-reference, a `/esq:<name>`, a README row, a `references/*.md` path, a brief section with a consumer) and *a format the code parses* (`check-conformance.sh`, against `docs/CONFORMANCE.md`). Beside them sit the package validator (`check-plugin.sh`), the no-push promise (`check-nopush.sh`), the manifest agreement (`check-release-version.sh`) and the node product suites. **Everything about what a document *says* is `docs/AUDIT.md`'s reading pass** — a dozen lexical guards lived here until 2026-09-22 and gave the false impression that pass had been mechanized.

**Three passes, and the flags add rather than re-buy.** Default is the product, node suites included — never run `node --test` beside it on the same tree. `--release` adds packaging and release; `--lab` adds the research fixture suites. Node suites are discovered by convention (`tests/{cli,hooks,audit}` for the product), never listed by hand: a hand-kept list is how two real suites went unrun for as long as they existed.

**A subprocess that can hang is never bare.** Node suites run through `scripts/check-bounded.sh <bound> <label> -- <cmd>`; a `claude plugin …` call carries an inline `timeout --kill-after=5`. Bounds are positional arguments so a test can inject a hang at 1 s, and every such call runs `claude --bare … </dev/null`.

### `scripts/lib/journey-runner.mjs` + `scripts/smoke-work-capture.mjs` + `scripts/smoke-journeys.mjs` + `tests/smoke/`, `tests/journeys/` — runtime evidence, billed once and replayed for free
**Owns:** proving a conformance scenario against a *running* Claude Code rather than against the prose. Per branch it copies the seed repo into a fresh `mktemp` root, git-inits it, and spawns `claude -p --model opus --plugin-dir <repo>/plugin --output-format stream-json --permission-mode bypassPermissions` there with `ESQ_TELEMETRY` off, killed at `--timeout`. That whole impure half is `scripts/lib/journey-runner.mjs`, which `createRunner({ seedDir, rows, harvest, … })` parameterizes: seeding, the legacy-shadow refusal, the bounded spawn, the stream reduction, the record write, the `--parse` replay and the table live there once, and a consumer script owns only its rows, its judges and its harvest. It was extracted for a second consumer that exists — `scripts/smoke-journeys.mjs`, B-032's orchestration journeys — not in anticipation of one, and the proof the extraction changed nothing is free and exact: `tests/smoke/fixtures/capture.jsonl` still replays four green without moving a byte. The `--timeout` it announces is a bound on the *tree*, not on one pid: the billed child is spawned `detached` so it leads its own process group, the deadline `SIGKILL`s that group, and a second short grace destroys the inherited pipes and resolves anyway — because a killed child's own children hold those pipes open and a deadline that waits for them is not a deadline (B-135). `detached` costs the terminal's `SIGINT`, and `live` repays it with a SIGINT/SIGTERM/SIGHUP trio installed for exactly the span a row's child is in flight — SIGHUP because a closed terminal or a dropped ssh session hangs up the foreground group the detached child left, and on the default disposition the runner would die there while the tree it started kept running, unwatched and still billing (D-kill-the-group-then-read-survivors). The `survivingProcesses` reading is taken after that reap and is never filtered: it is honest because of *when* it runs, not because of what it excludes — after `close` the child is already gone, and after a grace expiry whatever is still alive is a teardown the runner tried and failed to complete. So on a timed-out row that number says what outlived the runner's kill, the run's own `claude` included; `timedOut` is the verdict there, and the count beside it judges the harness's teardown rather than the phase's.

**Two consumers, two questions.** `smoke-work-capture.mjs` asks whether one command's *free-text capture* behaves (P-07), and judges a backlog: rows, IDs, capture commits. `smoke-journeys.mjs` asks whether an *orchestration* resumes, reconciles and refuses the way its own judges say, and judges a plan's ledger: the execution-log entry headings, the commits an entry cites, `esq validate` and the toy project's own `check.mjs`. Where they differ is the seed. A P-07 branch starts at a clean slate; a journey has to start *mid-orchestration* — a task already committed and unlogged, an entry left `⏸` — so the harness carries two hooks only journeys pass: `seedOverlay(row)` copies one journey's overlay over the same toy project (an overlay, never a fork — `tests/journeys/journeys.test.mjs` refuses an overlay that restates a seed file), and `postSeed` makes the commits the run must *find*, after which `seedHash` is re-read so pre-dated history can never be mistaken for the run's own work. What each script persists is decided in one place either way: `journey-evidence` declares the ledger facts a judge reads and, deliberately, not the plan file's text — no judge reads it, and publishing it would put the execution-log entry the model wrote into a public capture by another route. The live path bills (three active journeys — U-02's two and U-01's: $1.99, 170 s, Claude Code 2.1.251 on 2026-08-30); the `--parse` replay of `tests/journeys/fixtures/capture.jsonl` and one mutation per journey is free and runs under `./scripts/audit.sh --lab`.

**One probe beside them, sharing the write path and nothing else.** `scripts/probe-model-pins.mjs` and `scripts/probe-background-lifecycle.mjs` ask what the *harness* does, not what a command does, so they spawn their own short headless runs rather than seeding a repo through `createRunner`. What they share with the smoke pair is `scripts/lib/capture-schema.mjs`: the one table deciding what a billed capture may hold, reducing every record at construction so a field a future Claude Code adds is dropped rather than published. The background-lifecycle probe (B-085/B-087) measures, in three rows, which collection and teardown primitives resolve in a *worker*’s tool set, what a launch leaves registered, and what arrives after a synchronous `Agent` return — and the rule `/esq:build` now carries names only primitives that reading found. A key that measures *how long after* something happened is owed only when the boolean it hangs off came back true (D-a-conditional-answer-key-is-declared), and a lifecycle fact the platform could not read leaves its key **absent**, never empty — an empty `survivingProcesses` is a teardown that was read, a missing one is a platform that could not look (D-an-unreadable-teardown-is-absent-never-clean).

**A journey the product does not honor is parked, never loosened** (D-park-a-journey-never-loosen-its-judge). U-06's `escalation` journey reddened on two billed runs because `/esq:build` recorded no escalation over a trust boundary — a finding about the command, filed as **B-093**, not a judge to relax. It leaves `ROWS` for an exported `PARKED` list carrying its blocker and the path to its billed red capture, which is what B-093's row cites; its overlay and its judge stay checked in and the no-fork overlay rule still covers them, so deleting either reds; `--only escalation` refuses naming B-093 instead of re-buying a red; and `docs/CONFORMANCE.md` carries **no** runtime-evidence line for U-06, because a false line in the external referent is worse than a missing one. **The registry and its fixtures are a bijection** (D-the-registry-and-its-fixtures-are-a-bijection), asserted in two places because one was not enough: `judgeCapture` names every registry branch missing from a capture — the mirror of the unknown-row problem it already named — so `--parse` can never again print a green table shorter than `ROWS`, and `tests/journeys/journeys.test.mjs` asserts every active branch has exactly one row, one evidence record and one `mutated/<branch>.jsonl` while every parked branch has a `billed/<branch>.jsonl` and appears in neither. `--parse --only <branch>` is the one deliberate narrowing, for replaying a single-journey archive.
**Owns deliberately not:** the audit's job. It is never called from `audit.sh` — it bills.
**Entered by:** a human, deliberately; `--parse` replays a saved capture through the same judge for nothing, and refuses a terminal stdin rather than appearing to hang.
**Good to know:**
- **The verdict is read from artifacts, never from the model's prose** — the commits and their file lists, the ledger rows, `node check.mjs`. The run's own narration is recorded as corroboration and gates nothing (D-a-runtime-eval-judges-artifacts).
- Two refusals fire before a token is spent: an installed `~/.claude/commands/esq/` set (it would shadow the plugin under test) and no `claude` on `PATH`. **A billed run never overwrites paid evidence** (B-098, D-a-billed-run-never-overwrites-paid-evidence): a narrowed `--only` run has no default destination and refuses before the spawn without `--out`; an `--out` it was given is exclusive-created whatever the run turned out to be, red and partial captures included; the checked-in aggregate is a candidate only for a whole-registry run with no `--out` that completed every row, timed none out, serialized clean and re-judges green through `judgeCapture` — the same judge a `--parse` runs, not the verdicts the loop already printed (D-the-aggregate-is-earned-by-a-replay) — and is then taken by a same-directory temp file and one `rename`; every other outcome — a throw, a timeout, a lost `wx` race — keeps the paid records in a `mkdtemp` file the diagnostic names, and a zero-record run writes no file at all. Evidence already billed survives a failed branch, and no failure mode reaches a file that already exists.
- **`writeCapture` is the one write path, it takes an explicit `mode` with no default, and it never throws.** A missing or unknown mode, a serialization failure and a lost `wx` race each return a non-zero status having written nothing (D-the-one-write-path-never-throws). What still reaches it that way is the smoke runners' aggregate promotion, invoked from `live`'s outer `finally`, where a throw would replace the run's own outcome with the writer's — and no default mode means no caller reaches the destructive branch by omission. Everything a billed run produces row by row goes through `openCapture` instead (D-paid-rows-are-durable-before-the-next-one). **And a durability guarantee is worth only the path a contributor can find, so the sink is named on stderr before the first paid row** — a no-`--out` run's journal is an unpredictably-named `0700` `mkdtemp` directory, and a `SIGKILL`, a closed terminal or a signal between two rows leaves the rows on disk with no diagnostic behind them. For the same reason a run that produced records and could write none says it *bought* evidence it could not keep, never that it captured nothing: `written` is 0 on both paths, and only the records already in hand tell a full disk after a paid row apart from a run that never bought one.
- The judge is the free half, and `tests/smoke/` is its regression suite: `work-capture.test.mjs` holds the checked-in `fixtures/capture.jsonl` to four green plus one mutated copy per branch that must red it, and `runner.test.mjs` covers the harness underneath — a preamble before the first marker, a duplicate row, an unknown branch, and the two refusals (`--parse` on a terminal stdin, and a legacy install that would shadow the plugin) asserted with a stubbed `claude` first on `PATH` that must never be reached — a judge that never fails is not a judge. A mutated fixture carries the evidence records only, without the stream events, because the verdict rests on artifacts and a test pins that it does (D-a-mutated-fixture-carries-evidence-only).
- It exists because `claude plugin eval` — the vehicle B-032 names — refuses to run. Re-read on 2.1.251 (2026-08-29): `--help` renders a full surface, but `init` and the run path print `` `plugin eval` is currently in early access `` **and exit 0**, so a suite wired to its status would read green. The port back is B-074's, and whoever attempts it asserts on the absence of that line, never on the exit status; the native runner also has no free replay (D-runtime-evidence-from-a-bespoke-runner, D-journeys-stay-bespoke-on-2-1-251).

**A journey is a candidate before it is a row, and the aggregate is re-bought rather than appended.** The registry/fixture bijection and `--only`’s refusal to name an unknown branch deadlock a new journey: it cannot be bought until it is registered, and registering it before it is green reds the suite. So a third state exists — a full row resolved by `rowFor`, accepted by `--only` and by `--parse --only`, absent from `branches` — which a journey passes through rather than lives in (D-a-journey-is-a-candidate-before-it-is-a-row). Promotion is not an append: a journey enters `ROWS` only on a whole-registry run with no `--out` that completes every row and re-judges green, because `tests/journeys/fixtures/capture.jsonl` carries one Claude Code version’s claim on behalf of every row in it, and a hand-assembled aggregate would make that claim false by construction (D-the-journey-aggregate-is-re-bought-never-appended). Adding one journey therefore costs a re-buy of every row — five runs, ~$3.75 at 2026-09-09 prices — and the phase that promotes one states that bound before it spends.

### The machine-local instruments — `cost-budgets.mjs`, `measure-wait-cost.mjs`, `measure-rereads.mjs`, `docs/baselines/`

**A maintainer's research, and nothing the product reads.** Each of these reads one machine's telemetry store or its transcripts, which is exactly why none of them can gate anything: a measurement taken here would redden a commit it did not cause. They are run on demand; their *fixture* suites run under `./scripts/audit.sh --lab`, never in the default pass.

`docs/EVIDENCE.md` is the maintainer's ledger of billed harness measurements, appended by hand and read by `esq evidence`. **Nothing in the product reads it.** It used to: `esq evidence` computed a `relay` verdict that the three orchestrators consulted before their first spawn, and a project with no registry — which is every project but this one — was refused orchestration from any model but Opus. That preflight was removed on 2026-09-22, with the post-spawn model assertion beside it. The model policy is now one line in each orchestrator: workers are spawned with `model: opus`, a session on a cheaper model has them inherit it, and that is reported rather than stopped on.

## Key flows

### A skill change ships
1. Edit `plugin/skills/<name>/SKILL.md` (and `references/`, plus each moved procedure's `loaded-at` declaration, for a declared split skill — `build`, `plan`). 2. Update `README.md`: inventory, Mode discipline, Model recommendations, and re-read the prose. 4. Run the cost pass (the four questions). 5. Run the checks the change earns — a change crossing packages earns broader ones, never a standalone check beside an audit that runs it. 6. Commit. 7. Validate live with `claude --plugin-dir ./plugin` — never by installing from the worktree. The plan's final phase names `./scripts/audit.sh`, runs it and records its genuine PASS in the `verified` block, and `/esq:land` reuses that PASS when git proves it still describes `HEAD` or runs the audit once. No git hook runs it; exact-command reuse cannot remove every overlap between a phase's own check and the audit, and no subsystem is added to try (D-land-reuses-proved-verification).

### A shipping unit lands
`/esq:build` completes every phase, recording what each proved → `/esq:converge` closes the corrective loop (review → fix) or a standalone `/esq:review` comes back clean; a `/esq:fix` run that empties a `/esq:review`-originated brief hands back to `/esq:review` on the plan `esq brief plan <brief>` already resolved, and never calls the unit clean, covered or landable, because only a review records coverage (D-a-fix-hands-back-to-the-finder-that-found-it); either records the covered commit through `esq plan set-reviewed` and reports *ready to land* — neither merges → `/esq:status` routes a complete, covered, unmerged plan to `/esq:land`, a stale coverage to `/esq:review` (never the whole loop again), and stops recommending anything once it landed → `/esq:land <plan>` reads every fact in one call and stops, as a no-op naming the command that clears it, at the first prerequisite that fails, cheapest first — every one asked of the **unit**, every plan recording the branch, because the merge takes the whole branch: already `landed` (read before the branch verdict, which masks it from the destination; a deleted branch is read through the commit that last changed its plan file), no origin, HEAD not on the unit's branch, a dirty tree, a `unit.incomplete` plan (unbuilt or paused and not recorded abandoned — `/esq:build` on it, or `esq plan abandon` as the user's alternative), a ledger `esq validate` rejects, an undisposed `unit.open` or `unit.promised` row (an abandoned plan's promises included — a promised row whose whole delivery the landing can cite is closed there and then through `esq backlog set-status`, in one bookkeeping commit followed by a fresh verdict read, rather than handed back for the user to paste; completeness, split evidence and every `unit.open` row stay stops — D-a-landing-closes-the-delivery-it-can-cite), a live `unit.findings` brief, the unit's `coverage` not `covered` (any unit plan's `**Reviewed at:**` may cover `HEAD`), a `destination` landing site the same verdict already carries that is not `usable` (its own `git -C '<path>' …` command clears it, and it is asked last among the free facts because everything after it costs minutes) → only then `esq gate verify --unit` without `--workers-moved`, the union of every unit plan's `(auto)` steps deduplicated by exact command, each `run` executed at most once, collected once and torn down → `esq branch check <plan> --at <head> && esq merge land --plan <plan>` in one call, so a commit made while verification ran refuses as `moved` and never lands; the merge reads both refs from the header itself. A projection `esq projections` cannot prove fresh is one advisory line naming its owner, never a stop (D-projection-freshness-is-advice-at-landing). Publishing stays a separate step a person runs afterwards (`./scripts/update.sh`). There is no landing journal: a command a landing ran green is recorded nowhere, so a refused merge re-runs it next time (D-landing-is-its-own-command, D-a-landing-reads-coverage-and-obligations, D-land-verifies-the-whole-unit, D-a-unit-lands-when-every-plan-is-built-or-abandoned).

### A build phase at runtime
A red `(auto)` step whose cause the phase can name is repaired in place rather than handed back: at most **three repair edits per phase per invocation**, each against a cause this phase has not already spent one on, with the count printed as `repairs <n>/3` on the failure report and on the success line a repaired phase produces. `/esq:build` → `esq next-phase <plan> --context` (or `esq state`) decides ready / paused / complete from the execution log alone and, under the flag, hands back the plan context the phase agent would otherwise fetch in a second, dependent read stage — the plan section — ending at the `## Execution log` heading plus at most one line, that line taken only when it does not open a `### ` heading, so the append anchor is carried where the log has one and an entry's heading never is (D-the-plan-slice-stops-before-an-entry-heading) — any post-log appendix, and the newest log entry plus the `⏸` entry that same response classified (never one re-derived by a second priority), as source text with 1-based ranges (D-build-asks-the-cli-for-its-plan-context); the `shared:log-skeleton` grep stays as the CLI-unavailable fallback and as `/esq:autopilot`'s own route → the skill does the work with atomic commits → this phase's backlog candidates are committed and `unit.open` recomputed over them, then `esq plan append-log <plan> <json>` writes the entry (refuses a duplicate phase, a missing log section, and a `completed` entry carrying no `verified` block where the phase's own verification names a resolvable `(auto)` command) → on stop, `validate-stop.mjs` runs `esq validate`; a defect in *this session's* uncommitted ledger changes blocks once with the findings. Resume is the same read: a `⏸` entry is the state, no sidecar (D-narrow-the-read-not-the-plan-file) — two clauses today (`awaiting manual verification`, `blocked on an open same-unit defect`), and every consumer routes on the glyph, never on the clause. `append-log` also refuses a `completed` entry while `esq branch check`'s `unit.open` is non-empty: a 🐛/⚠️ row whose `Source` names a `build:`/`fix:` step of this shipping unit — every plan recording the same `**Branch:**` — and whose `Status` is neither `Done` nor `Dropped`. Three table cells and one header field decide it; the gate never inspects which file the defect is in, so it blocks wider than "a defect against this unit's own code" reads, never narrower. `/esq:converge` reads the same block at preflight and refuses before its first spawn. The pause that gate causes has one way out and it is a CLI write, not an edit: `esq plan resolve-block <plan>` answers read-only while any blocker stands — naming the pause `nextPhase` selects, the same classification `/esq:build` routes on, never a second walk of the log's insertion order (D-resolve-block-selects-through-nextphase) — and `--confirm` re-derives the unit, the dispositions and the phase's own `(auto)` freshness before rewriting the entry once — `**Blocked by:**` becomes `**Blocked by (resolved):**` carrying each row's disposition, and the entry becomes `completed` or stays paused under the manual clause. A command git cannot prove green and the payload does not name is refused, which is how a red rerun holds the pause; every refusal leaves the plan byte-identical, so the whole path is repeatable after an interruption and re-runs no task.

### Billing a subagent
An orchestrator starts every `Agent` description with `esq:<command>` → `PostToolUse` stores that slug alone as an `AgentLabel` row keyed by `agentId` → `SubagentStop` streams the agent transcript, keeping ids/model/usage/tool counts, and appends the run under a claim file, over a fallback row that landed first → the run continues; nothing asserts what the worker actually ran on, and a session on a cheaper model has its workers inherit it (orchestrate from an Opus session; re-probe) while `unknown` stays a fact line → `esq telemetry summary` keeps the whole-run record per `agentId`, joins label to run by `agentId` and sums per esq command, agent type and model — and per command × model, with what was asked beside what ran — medians beside totals. The description prefix is the **only** join key (D-esq-spawns-labelled-by-description-prefix); an interrupted subagent fires no `SubagentStop` and leaves no row (B-036, named in the output). The direct path bills the command itself rather than its agents: `Stop` / `SessionEnd` → `record-session-telemetry.mjs` → `telemetry/session-runs.jsonl`, joined on nothing — each row is grouped by the slug of the opener that started its segment (`via: typed | skill-tool`), kept last-row-wins per `(sessionId, segment)`, and summed by `esq telemetry summary` into its own `direct sessions · by command` section, never into the subagent tables (D-direct-session-telemetry-stop-cursor).

**Every row also carries a repository key, and the rows that matter carry a plan identity (B-121).** The telemetry store is machine-wide — `discoverTelemetryFiles` pools every `~/.claude/plugins/data/esq-*` directory — so a plan slug, a *repository-local* name, is not an identity on its own. `repoKey` is 32 hex characters of SHA-256 over the **canonical git common directory**: `<root>/.git` for a main checkout, and for a linked worktree the same directory, reached by following the `gitdir:` file and reducing a trailing `/worktrees/<name>`, so `scripts/worktree.sh`'s worktrees key as their checkout while two clones of one project key apart. It is never a path, a name, a remote or a branch, and 128 bits rather than a truncation because a short-key collision *plus* a same-slug plan would produce a wrong attribution rather than a visible foreign row. **It goes on every row both writers emit** — agent label, subagent fallback, whole-run record, direct segment, ambiguous rows included — regardless of command class and regardless of whether a slug is there, and that is not incidental: the rows coverage weighs are exactly the ones with **no** slug, so a key written only beside a slug would leave every miss unscoped and indistinguishable from another project's run (D-invalid-samples-excluded-not-deleted, amended). Widening a deliberately minimal store is taken on those terms, and `telemetryOptedOut` gates the key exactly as it gates every other write.

**Plan identity is declared, in the spawn description and nowhere else.** The orchestrator's `Agent` description carries `esq:<command>` and, when the orchestrator was itself invoked on that plan, an explicit `plan:<slug>` marker. The prefix is required because a description is free prose and a *bare* second token cannot be told from it — `esq:build phase 2 of the plan` would persist `phase` (D-plan-identity-is-declared-not-inferred). **The marker admits the plan file's dated stem as well as the bare slug, and the writer canonicalizes it**: every one of the first seventeen markers ever written carried the stem, against prose that had stated the rule correctly three times, so the derivation moved off the instruction and onto the machine that stores the value. `canonicalPlanSlug` in `hook-io.mjs` is the **one** definition of that stripping, shared with the CLI's plan index, because the two must agree byte for byte or every row de-joins from the plan it names.

A second path existed until 2026-09-22: `esq lane` appended a `{ slug, repoKey, at }` event to a session-scoped log that the session recorder consumed and unlinked, so a *directly typed* command could claim an identity too. That verb retired with the assurance lanes, and the log went with it — a reader that always finds nothing is not a mechanism. A direct session row now carries its `repoKey` and no plan, which is a *missing* identity: the failure this design has always preferred to a wrong one.

A session id is **hashed into a filename, never interpolated into a path**: `sessionKey(id)` rejects a non-string, an empty string or an id over 512 characters and otherwise returns the first 32 hex characters of its SHA-256 — fixed-length, hex-only, traversal-proof by construction.

**The writers enforce shape only** — the closed `^[a-z0-9][a-z0-9-]{0,63}$`, no separators, no dots, no path — because a hook owns structure and never judgment. Every row is scoped before it is read: `repoKey` equal to this repository's is *local*, a different key is another repository's, an absent key is a pre-B-121 row, and the last two belong in no denominator.

## Rules
- **Skills judge, the CLI structures.** Any operation with an exact answer over a ledger or plan file goes through `esq`, never prose — *why:* prose execution made exact operations probabilistic; the CLI makes them atomic and testable (D-cli-owns-structure-model-owns-judgment). The converse holds: the CLI never picks an approach or a severity.
- **One writer per ledger file, named in the table above** — *why:* a file written from two commands drifts, and `esq validate` can only hold an invariant one writer promised.
- **A shared paragraph is marker-delimited and registered once** — *why:* command files cannot reference each other at runtime, so rules are copied; unmarked copies drifted by ~2,100 words by 2026-08-14. Inside the markers only what is identical by design (D-shared-only-what-is-identical-by-design). The standing exception is a rule two commands reach independently rather than copy: `/esq:roadmap`'s rolled-up `blocked` state and `/esq:advance`'s step-4 classification each state the `needs:` resolution — an edge blocks only while its target is still an entry in a horizon, never on presence in the self-pruning `## Shipped` tail — in their own words, unmarked and unregistered, held together only by review. It is written down here because a second correction of that rule is the point at which it earns a check rather than another reading (D-needs-blocks-on-queue-presence).
- **Every long-running command announces its bound before its first tool call and reports elapsed after** — *why:* `/esq:plan` spawned nothing, ran 8 minutes silent, and was killed as hung. It is an instruction each skill honors, not a linted string: a lexical check cannot tell a stated bound from an honored one, which is why the guard that policed it retired on 2026-09-22 and the reading pass owns it. **The announcement is one line, and the first tool call follows it in the same response;** zone 2 holds only requests the user still has to settle, each executable one carrying its exact command, and `→ Next` repeats the first — *why:* 5 of ~500 invocations stopped after "I'll start with the announcement", a phrase every announce block quoted as its anti-example; the rule is written into every announce block, and the intermittent stop is gone (D-announcements-and-asks-stay-minimal).

- **What is independent is issued together; what is ordered is chained in one call; git mutations are never issued side by side.** The rule ships as the marked `shared:batch-independent` paragraph copied into six skills — read-once's five workers plus `plan` — and registered once in `check-sharedblocks.sh`, beside `shared:read-once` and subordinate to it: batching decides which turn a call lands in, never whether a call the run does not need happens at all — *why:* the round trip is the unit this system is billed in, and esq's own agents issued 1.068 tool calls per turn against 1.243 for the 446 non-esq agents on the same machine (621 subagent transcripts, 2026-08-21), a gap worth ~4.0 round trips per run. - **A command's own bookkeeping costs one commit, not two.** Where a command owns every file in its tail in the same pass, those writes are staged together: the fixes brief with the backlog rows it escalates (`check`, `review`, `fix`), the plan file with its decisions, the status flip it caused and the corrective brief it retired (`plan`), the plan anchor with the backlog close (`work`) — *why:* reverting a plan should revert the status flip it caused, and a split tail bought a round trip per run for a separation nothing reads. It never reaches implementation commits, which stay atomic so a fix can be reverted alone; `/esq:work`'s amended count (three things, two commits) is pinned in `docs/CONFORMANCE.md` rather than left to prose.
- **A plan audits itself before it is presented, in the context it already holds.** Nine checks — no lifecycle step another command owns, completion stated apart from post-ship measurement, no contradiction between `## Done looks like`, the exclusions, the phases and `## Risks`, any public-surface widening made explicit, boundary and malformed-input cases covered, activation and deployment named, every `(auto)` command resolved against its own script's usage, no phase's mandatory verification buying one proof twice (D-a-phase-buys-each-proof-once), every phase within four tasks — corrected in place, with only a genuine product-policy choice ever becoming a question, and that one riding the questionnaire already being sent — *why:* an ordinary omission otherwise costs a full `/esq:check` subagent to find, one command and one session later; the bound (no subagent, no extra artifact, no re-read) is what keeps the self-audit from becoming a second finder charged at a finder's price.
- **A phase's mandatory verification buys each proof once, and the choice is made where the obligation is written.** Before a phase's `(auto)` set is final, `/esq:plan` reads what each command actually *selects* — the package script it resolves to, the paths and config that decide which tests run, the environment it sets — and prescribes the broader command alone where it already buys a narrower one's tests **and** its PASS criterion under equivalent conditions. It decides one phase's own set and never the plan's, so an earlier phase's targeted step survives a later phase's whole-repo run, and the blast-radius half of the same bullet keeps deciding when a phase earns the wide one — *why:* a shipped plan declared a jest subset (22 suites, 580 tests, 148.972 s) beside the same runner under the same environment with no path filter at all (62 suites, 1358 tests, 173.908 s), and `esq gate verify` correctly enforced both at one landing with the first's 580 tests re-run inside the second's 1358 — nothing misbehaved, the redundancy was *authored*, so it is removed where obligations are authored (D-a-phase-buys-each-proof-once). - **A run records the verification it earned, and a recording item's path is chosen before that verification runs.** `/esq:fix` appends its proof through `esq plan record-verification`, and the order is fixed at the moment the item is classified, never in the branch that discovers it passed: stage → `git write-tree` → **one** verification run → judge the step's own criterion sentence → commit the fix → record and commit the proof. The proof is its own bookkeeping commit, because the verb needs the fix commit's oid and tree and amending it would move the tree it certifies; that commit is invisible to the gate because an append below `## Execution log` already compares equal on the plan section — *why:* choosing the path after the result, or describing one order in the loop and another in the recording section, makes a literal reader run the same `(auto)` step twice per item — here a ~3-minute audit — which is precisely the paid-work-done-twice this transmission exists to remove, and no test or conformance clause catches an ordering that lives only in prose. The failure branch unstages as well as restoring (`git restore --staged --worktree <touched files>`), because a recording item staged before it verified and a bare `git restore` restores the worktree *from the index*, leaving the red change for the next item's commit to carry and the next `git write-tree` to certify (D-a-fix-records-what-it-proved; the ordering and the unstaging form were both caught by this unit's own review pass, not by a check, which is why the rule is written here and pinned by `docs/CONFORMANCE.md` R-10).
- **An `(auto)` step's verdict never depends on which implementation of an ambient tool the shell resolves, and a prose sweep is judged against the property its step describes rather than against the set of matches its command returned.** Explicit path operands over a search root plus a path-prefix filter; the class also covers a line-based match blind to a claim wrapped across a line break, a locale-dependent `sort`, and GNU versus BSD `date` — *why:* a stem plan's `^./` filter excluded an archive under GNU grep and excluded nothing at all under the ugrep shim Claude Code's Bash tool resolves, so 102 matches stood in for 1150 and a whole phase read green having verified nothing; the occurrence the command cannot see is corrected anyway and the gap recorded, because a rule stated as a fact about one tool is one tool away from being re-learned (D-an-auto-step-names-the-tool-it-means, D-a-prose-sweep-corrects-what-its-grep-cannot-see).
- **A path this repository retired stays retired because a check holds it, never because a plan step swept it once** — the guard judges each file's *path* as well as its content and ships its own fault injection, and every record of the retirement names the thing that retired rather than the path, which is spelled only where a reader must act on it — *why:* a verification step runs once and the path returns with the next session that remembers it; a reintroduced directory carries the banned literal in neither its lines nor its prose, and a repository that keeps spelling the path cannot hold it banned (D-a-retired-path-is-held-by-a-check, D-a-path-guard-reads-the-path-not-only-the-content, D-a-retirement-record-names-the-thing-not-the-path).
- **A guard another rail makes unreachable is kept, said to be unreachable, and tested on what is observable.** The code comment names why it cannot fire and what would make it reachable, and the test asserts the neighbouring observable property rather than manufacturing a state no run produces — *why:* deleting it is silent (relax the rail and the hole opens with nothing recording what it protected), and leaving it undocumented is worse, because a guard nobody can trigger reads as dead code to the next person who notices. Today's instance is `record-verification`'s duplicate-proof refusal, unreachable while `at` must equal `HEAD`: a block naming HEAD's own object id cannot already sit inside HEAD's own tree. Any change letting `at` name another commit owes that branch a test the same day (D-an-unreachable-rail-is-kept-and-said-so).
- **A defect against the shipping unit is not a backlog row.** *Out of scope* means outside the **unit** — every plan recording the same `**Branch:**` — not outside the phase: an ordinary omission in code the unit wrote is corrected in the task's own commit, a substantive one pauses the phase with `blockedBy` naming the rows, and `esq plan append-log` refuses a `completed` entry while any undisposed 🐛/⚠️ row whose `Source` names a `build:` or `fix:` step of the unit stands. `/esq:converge` reads the same list before its first spawn and again before it records a clean completion, and `/esq:land` refuses on it beside `unit.promised` and `unit.findings`. The join is three table cells plus one header field: it judges no severity and never opens the file the failure is in, so it blocks **wider** than the prose rule reads and never narrower — a 🐛 the phase files about code outside the unit stops it too, deliberately — *why:* a row filed against the unit's own code went nowhere any later step could read it (`/esq:autopilot` reads no entry body, `/esq:converge`'s preflight opened no backlog, both finders pathspec-exclude `docs/BACKLOG.md` from their diff), so the only way such a defect came back was a paid finder rediscovering it, and each rediscovery bought a whole corrective plan — the `plan → -fixes → -fixes-fixes` chain of 2026-09-09. The disposition that releases it is written through `esq backlog set-status` — by `/esq:backlog`, or by the command whose own evidence proves the promised outcome delivered and verified — and never to get past the gate: nothing is dropped, re-filed or re-sourced to clear `unit.open`, and a finding is filed `observed:` (non-blocking) only when it lies outside the promised work and the unit neither introduced nor aggravated it, an untouched file or a pre-existing failure proving neither (D-evidence-settles-backlog-dispositions, which replaced a drop-and-re-file dance run twice in one phase); what *reads* that disposition back and moves the phase is `esq plan resolve-block`, so the pause the gate causes is exited by a deterministic write that refuses rather than by a skill rewriting the entry — scenario U-11. **And the gate only sees what has already been filed, so the order of the two writes is part of the rule**: a phase commits its backlog candidates first, recomputes `unit.open` after them, and only then appends its entry — a row filed *after* the entry is a row the entry never had to face, which is the same defect by a later route, and an interruption between the two commits reconciles the task commits, files nothing twice and lands on the blocked pause (scenario U-10) (D-a-same-unit-defect-is-never-a-backlog-row, D-the-unit-is-keyed-on-branch).

- **A diagnosed failure whose fix is already written is applied, under a budget the report prints.** A phase that can name the cause of a red `(auto)` step applies the fix itself, bounded by three repair edits per phase per invocation and by a distinct-cause rule — an attempt is legitimate only against a cause this phase has not already spent one on, and a second red from the same cause is exhaustion, not a new attempt. The budget lives strictly inside one invocation, so `/esq:autopilot`, `/esq:advance` and `/esq:converge` keep their "never retries a reported failure" rule untouched (D-a-repair-budget-replaces-the-ceiling).
- **A corrective chain opens at most two plan generations.** Consumers ask `esq brief depth`, never count suffixes. Exhaustion routes safe fixes through `/esq:fix` → `/esq:review`; no new generation or completed-plan abandonment is proposed. The project file wins where it speaks and the default covers the rest. **`docs/STANDARDS.md` has no writer**: it is read by all ten authors of a 🔴 and created, edited and migrated by nothing in esq, which is why it is absent from the one-writer-per-file table above — it is a project's input to esq, not a ledger esq maintains. The consult itself is one paragraph appended to the host line of both ask families rather than a third block, so the two shared ask blocks can still agree internally after a carrier loses that consult; the loss belongs to the human reading pass, not a lexical guard (D-the-consult-rides-both-ask-block-families) — *why:* a stated constraint was an absolute ask trigger in all ten authors, and B-169's specimen 2 is what that cost — a 265px overrun against a 4800px budget written into `## Done looks like` stopped a run to ask whether 5.5% was acceptable, with no written standard anywhere in `docs/` or `plugin/skills/` to arbitrate it against. A `references/` file under one skill could not have served it: `CLAUDE_SKILL_DIR` names only the running skill's own directory, so nine of the ten carriers would resolve the path to a file that does not exist, and a hard-coded absolute path breaks on every machine but the author's. Filling part 2 permissively is the failure direction to watch — a class wrongly marked arbitrable ships a violated constraint silently, where a class wrongly left hard costs one 🔴 the user can answer (D-a-standard-arbitrates-a-stated-constraint, D-the-referent-ships-in-the-plugin-and-the-cli-resolves-it).
- **Cost is audited on every change** (CLAUDE.md's four questions) — *why:* both defects of 2026-08-12 shipped inside a change meant to reduce cost, and were found only because someone asked (`docs/AUDIT.md § 5`).

## Boundaries not to cross
- **Nothing under `~/.claude/` is source.** The PreToolUse hook denies edits to the installed plugin cache. A `~/.claude/commands/esq/` set left from before 2026-09-22 has no guard at all — editing it is hot-reloaded, unversioned, and shadows the plugin — and nothing in this repository installs or removes it any more: delete the directory by hand.
- **The release path's only installation write is the official `claude plugin update` call.** `scripts/update.sh` publishes already-verified changes; it runs no audit and never switches branches, stashes or commits unrelated work. It requires clean `main` and asks `check-release-version.sh . --json` for source drift. Both a successful exit and a boolean `releaseNeeded` are required. `true` delegates to `release-local.sh --patch`; `false` delegates to `--check` and reports that no new release is needed, **not** that the installation is current. Invalid verdicts refuse, diagnostics remain visible, and delegate failures propagate. A pending release is a normal report at exit 0, never an audit finding.
  - The release primitive also requires the primary checkout and plugin changes since the last bump. Before editing versions it reads `known_marketplaces.json`: `esquisse` must use a directory source whose path and install location resolve to this checkout (symlinks allowed). Missing, unreadable, remote or mismatched registration refuses before any commit and prints the official registration and installation commands; `--check` reports the same diagnosis without mutating. Registration repair is a separate official CLI operation, never an automatic release side effect. It changes only the two manifest versions. Before committing, `git status --porcelain --untracked-files=all` must contain exactly those manifests and their diffs must contain only the expected version edits. A failed pre-commit proof restores those edits; unrelated files are never removed. It does not repeat plugin validation: that belongs to `audit.sh` before publication.
  - The official updater runs once as `claude --bare plugin update esq@esquisse --scope user --yes`, with stdin closed and a timeout. No direct cache or manifest writes occur under `~/.claude`. The script only reads `installed_plugins.json` and the installed tree to prove the version, release commit and full byte equality with `plugin/`. Missing harness fields or mismatches fail explicitly; the harness record is undocumented state owned by Claude Code.
  - **After the release commit, never rewind.** An install failure, timeout or failed proof leaves that commit in place and prints the official retry command. A successful release proves all three installation facts. Nothing pushes or tags. `release-local.sh --check` only reports and exits 0 even for absent or mismatched installations; it is not a validation gate.
  - The scripts live in the source checkout so a repair to the updater runs from the code being released, not an older installed copy. `test-update-guard.sh` and `test-release-local.sh`, under `audit.sh --release`, exercise their behavior in disposable repositories with stub commands and isolated configuration. Plugin-management subprocess fixtures also test bare mode, closed stdin and bounded failure without touching the maintainer's installation.
- **The CLI does not import a skill and a skill does not reimplement the CLI.** A skill parsing a backlog table or an execution log by hand reintroduces the probabilistic path the CLI exists to remove; a CLI subcommand choosing severity or scope encodes judgment without context.
- **A hook does not decide semantics.** No Stop hook emits completion or gate notifications, no PostToolUse hook runs the audit — the producing skill knows the phase and gate; a hook reconstructing that from prose notifies on unrelated turns and audits transient states.
- **`plugin/skills/` holds exactly the twenty-one distributed skills.** Fixtures, probes and project skills live outside it (`tests/fixtures/`, `.claude/skills/`) — the structure check discovers the corpus and verifies references, while `claude plugin validate --strict` validates the package under `plugin/`.
- **`esq branch check` is the only thing that decides branch ownership, and no command resolves a branch on its own.** The verdict is computed once, in `cli.mjs`, from the current branch, the plan's `**Branch:**` field and every other *shipping unit's* recorded branch — the repository's default branch is not an input at all, and `origin` rides in the verdict as a reported fact no consumer routes off; **three commands call it, all in preflight, all routing off its `refuse` flag and its exit code and never off the prose** — `/esq:land` too, which reads `landed` *before* `refuse` because a finished unit is usually inspected from its destination, where the verdict is `mismatch`, and which asks it once more as `--at <head>` chained into the merge, the one call where a `HEAD` or branch tip that moved since verification refuses as `moved`; of the other two: `/esq:build` calls it *before* it reads the plan file, because a refusal that costs one subprocess is cheaper than the read it prevents; `/esq:converge` calls it *before its first spawn* (the same ordering), because that same subprocess is cheaper than the four Opus subagents whose fix commits would otherwise be written onto a branch nobody will merge, under a run that still reports success — `esq merge land` takes both refs from the plan header and lands them correctly from anywhere, so the merge was never the exposure (B-119). Three rules ride inside it. **Ownership is a claim between shipping units, and `**Origin:**` is the marker**: a plan recording no origin is legacy — it neither claims a branch against another plan nor counts as an owner of one — because thirty-odd plans in this repository record `**Branch:** main` and treating each as an owner of `main` would make every one of them unbuildable. Its `**Branch:**` field keeps its build-time meaning, so a mismatch still refuses; it simply never lands. This replaced trunk mode on 2026-09-04, which exempted the repository default by name and stopped working the moment a shipping unit could be created from any branch. **Ownership alone refuses**, merged or not, exempting only plans sharing a slug stem (`x.md` and `x-fixes.md` are one shipping unit); `merged` is reported as a fact for the message and never decides, and it is three-state — `true` by ancestry, `'equivalent'` for a branch whose every commit the origin already carries by patch (cherry-picked or rebased), `false` still in flight — because ancestry is not identity and reading a cherry-picked stem as in flight is what sent a correction onto a branch nobody would merge again (B-138); a squash-merged stem is patch-equivalent to no single commit and still reads in flight, which is the residue that verb keeps. And **absence authorizes nothing**: no `**Branch:**` field is the `unrecorded` verdict, which refuses nothing and is what grandfathers every plan written before the field existed. **A worktree cannot see another worktree's plans** — ownership is computed from `docs/plans/` in the current working tree, so two linked worktrees can each record the same branch name without either verdict seeing the other; git's own refusal to check one branch out twice is what actually prevents that collision, and the verdict says what it can see rather than implying repo-wide knowledge. **The same verdict also carries the shipping unit**: which plans record this branch, and `unit.open`, the undisposed 🐛/⚠️ backlog rows a `build:` or `fix:` step of one of them filed — the gate `esq plan append-log`, `/esq:converge` and `/esq:land` refuse on, computed from `Type`, `Source` and `Status` cells plus the header field, opening no file a defect is named in. Beside it ride the landing's facts, each structure and never a judgment: `unit.incomplete` (every unit plan neither complete nor carrying a standing `**Abandoned:**` line — a marker on a plan built afterwards is inert) and `unit.abandoned`, `unit.promised` (undisposed rows `Planned by` a unit slug, `Needs-decision` included — delivery is recorded through `esq backlog set-status`, by `/esq:backlog` or by the landing itself when it can cite the commit or execution-log line delivering the whole row, and never inferred from the unit being complete), `unit.findings` (corrective briefs still on disk whose `Source` names a unit plan — a deleted brief is resolved), `landed` (the same three-state reading as `merged`, against the plan's origin) and `coverage` (`covered` / `stale` / `corrected` / `unproven`, from any unit plan's `**Reviewed at:**` against the projection harmless list plus prospective plan-contract changes, with `coverage.plan` naming whose record decided — and, when no record is usable, `corrected` rather than `unproven` whenever a `/esq:review` brief for a unit plan is still reachable from `HEAD`, which is the CLI-owned difference between owing one delta review and owing the whole corrective itinerary) (D-a-landing-reads-coverage-and-obligations, D-land-verifies-the-whole-unit). The refusal is an **authority** stop: the calling command hands back an option set and never switches a branch or edits the field itself (scenario R-06). **Single-writer binds commands, never the human, and what is handed back has to run.** `/esq:plan` owning `**Branch:**` is a rule about commands; the user editing their own plan header is the escape, so option A on a refusal carries *two* steps — `git switch -c esq/<slug>`, then, unless the header already names it, the header edit — because the switch alone lands the user straight back on the same verdict. An option set whose `do:` leads to a refusal is a `do:` that does not run, which is the whole point of the shape (B-120; scenario R-06 pins the second step in both carriers).
- **A landing gate re-runs a phase's `(auto)` verification only where git cannot prove the last green result still describes `HEAD`.** `/esq:build` records the provenance — `esq plan append-log`'s `verified` block: the **full** commit its steps ran on (a ref that can move is refused at append time) and the exact commands whose complete step it judged **PASS**, never an exit code; a `completed` entry that omits the block is **refused** wherever the phase's verification names at least one resolvable `(auto)` command, in the same call the worker was already making rather than by a later sweep that would find it when the only honest repairs left are re-running the commands or inventing them, while a `paused` entry keeps it optional because a pause released through `esq plan resolve-block` is already made to prove every owed command green (D-a-completed-phase-records-what-proved-it). **That block has a second writer.** `/esq:fix` records the proof a recording item earned through `esq plan record-verification`, so a phase can carry more than one, `parseVerified` returns every block a phase records rather than its first, and each is judged on its own `at` — a stale earlier block never shadows a fresher later one, and where a block sits relative to another phase's entry is readability and not attribution (D-a-fix-records-what-it-proved) — and `esq gate verify` answers, per distinct command, `reuse` or `run` with the reason named, returning decisions and exact strings while the orchestrator keeps execution ownership (D-cli-owns-structure-model-owns-judgment). `reuse` needs all four of a block on that occurrence's phase, an `at` git resolves, the command in its green list, and every path changed since harmless — the command-owned lifecycle gates 2, 3 and 5 already cover, which is not `docs/ROADMAP.md` and not `docs/epics/`; occurrences are read newest phase first and the selected one's **complete step text** travels, because the criterion is what makes an exit-1 `grep` a pass. An unresolvable step is returned shaped and run in full, never dropped or deduplicated, and `--workers-moved` forces everything after a fix or apply worker moved `HEAD` — which is why `/esq:land`, spawning no worker and making at most one backlog bookkeeping commit before verification, never passes it; the gate judges proof against the current `HEAD` after that commit. `--unit` asks the same question of every plan recording the branch — one union, exact-command dedup across plans, the newest proof deciding, an abandoned plan's unbuilt phases left out — because a `-fixes` commit can stale a test only the initial plan names. The plan-section comparison leaves out exactly two lines, the `**Reviewed at:**` and `**Abandoned:**` header fields, and the diff runs `--no-renames` so a rename reports the path it left; a projection refresh still invalidates, so a refresh after the final phase costs one re-run of what it touched (D-land-reuses-proved-verification). **What counts as changed can be narrowed by the step itself, and only by the step itself.** An `(auto)` step may declare the repository paths its command reads — `` `(reads)` `` and inline-code path spans after the property sentence — and the gate then judges *that one command's* freshness against those paths alone, matched by whole path segment and never as a glob. It is authored by `/esq:plan`, never inferred by the CLI. Provenance, the green list and `--workers-moved` remain unconditional checks, and a changed prospective plan section always invalidates. Input scope is resolved **before lifecycle exemptions**: a changed plain command operand or path covered by a valid declaration invalidates even when it is a ledger, another plan/brief, or the proof plan itself (including its execution log and bookkeeping header fields). Unread bookkeeping remains harmless; unrelated paths can still be excluded by a valid declaration. The gate does not discover undeclared indirect dependencies. It is ignored whole, and the command runs, when it names no path, carries prose, names an absolute path, a `.`/`..` segment or a glob, or fails to cover a path operand the command itself names; the operand rail is a crude read of the command string and errs only toward running. **And what the gate checks is shape, never completeness** — the declaration's syntax, and the paths the command names out loud, with a command form it cannot decompose refused whole rather than interpreted; a suite's imports, a runner's configuration and a binary the command spawns are invisible to a command string, so an accepted declaration is one the gate could not refuse rather than one it verified, and completeness is the author's to establish. A declaration lives above `## Execution log`, so editing one stales that plan's own proofs through the rule already there. The `run` reason names the whole invalidating set, bounded, rather than its first path, because a declaration can only be written truthfully by someone who can see that set (D-a-step-declares-what-it-reads) — *why:* the gate re-bought a 9m30 suite over the exact tree a phase had already proved green, and a gate that costs more than it can catch is the one people start skipping; and at one measured landing four required commands ran where three were owed, the fourth invalidated by eight paths the suite does not read (scenario R-09).
- **Coverage subsumption is decided when the obligation is written, never inferred at the gate.** `esq gate verify` matches commands literally: a broader command's PASS is never provenance for a command it does not literally match, no declared `(auto)` step is skipped, rewritten or deduplicated away to obtain reuse, and a plan already written keeps every obligation it declared — *why:* containment cannot be read soundly off a command string (jest path filters, package-script indirection, `testPathIgnorePatterns`), so a gate that inferred it would lower a correctness condition on every landing to save minutes on some, and its failure mode is a silently dropped obligation rather than a visible red. The same line refuses a CLI coverage cache, an attestation, and any migration that rewrites a completed plan to obtain reuse; the authoring rule costs nothing at runtime and cannot drop an obligation that was never written (D-a-phase-buys-each-proof-once). A `(reads)` declaration is not a hole in this and must not be read as one: it credits no command's PASS to another, deduplicates nothing, skips no declared step and rewrites no completed plan — the only thing it moves is *which changed paths count against one command's own recorded proof*, which is freshness rather than coverage (D-a-step-declares-what-it-reads).
- **A chosen option is routed before an agent is bought for it, and a relayed one is selected rather than applied.** The three orchestrators call `esq apply route` over the whole option set *before* the question they put to the user (`orch-shared:route-do`), and `orch-shared:apply-agent` spawns on `route: apply` alone: `relay` prints the command flush-left and stops the gate — never invoking the restricted skill, and never reaching the same end by its CLI call, a hand edit or a manual merge, because the restriction is on the action and not on its spelling — while `stop` spawns nothing on a string the run cannot place. `/esq:converge` then records the answer without its effect: one `Selected:` line in that 🔴, committed as `brief(selected):`, the red left standing, and on resume that line is the answer rather than the question again — the itinerary moves only on `applied: true`, which strikes the red as `brief(decided):` and resumes at the step *after* the one that gated; `false` reprints the command and stops; `null` says the tree cannot settle it and hands off, erasing nothing (D-executability-is-read-from-the-skill, D-a-relayed-decision-is-selected-until-state-confirms-it) — *why:* fourteen of the twenty-one skills carry `disable-model-invocation: true`, so the commonest `do:` of all bought a subagent forbidden to run it while the authorized decision stayed unapplied (B-092); a relayed gate therefore adds no apply agent to the announced bound, and a decision is never put twice. **A `stop` pick is never handed off as a command** — not flush-left, not cut to a command it mentions, not a `→ Next`: the orchestrator reads only what the chosen option names and proposes a repair of *that same action* (keeps · now · deferred · verify · does not) for the user to approve, asks first when the outcome is unstated or nothing is named to record it against, never respells a user-only action to make it route `apply`, and routes the approved replacement exactly once — the original is history, and a repair that routes `stop`, cannot apply or fails verification ends the attempt, a replacement being proposed only on a resume the user chooses; `/esq:converge` keeps that as append-only brief history (`Selected:` · `Repair approved #n` · `Paused:` · `Repair failed #n`) whose **last line** is the effective state on resume (D-unclassifiable-do-is-quoted-never-handed-off, D-a-repair-is-routed-as-the-action-taken) — *why:* in one downstream project a mixed `do:` routed `stop` correctly and converge then told the user to run the deferred `/esq:spec` at once; the router stays a one-token recognizer rather than a timing parser, and a history read from its first approval would re-route a malformed repair on every resume. **And an apply worker commits — in converge, strikes — only once its verification passes, for an ordinary option as for a repair:** a change it cannot apply makes no edit, one that fails verification commits, strikes, resets and discards nothing and reports the edits it left, and every orchestrator stops on it — `advance` walks on only over a clean tree, so failed edits are its dirty-tree halt (D-failed-verification-commits-nothing) — *why:* a template silent on the red path committed a failed repair and struck its 🔴, and an automatic revert, the only way to "change nothing", can destroy work already in the tree. Scenario U-13 pins the clauses, and it pins prose only: nothing observes whether a live run obeyed it.
- **A re-review narrows only to a commit a review read, and the commit subject is what tells them apart.** `/esq:review` resolves its whole scope through the read-only `esq review scope <plan>` and carries no procedure for computing any part of it; every failure there answers full scope, never a narrower one (D-review-scope-is-one-deterministic-query). The delta base that query returns is the newer of two history reads: a `brief(fixes): <slug>` brief whose `Source:` is exactly `/esq:review on <slug>,` (the comma ends the slug, the delimiter `unitFindings` keys on), and the `**Reviewed at:**` recorded by the newest `^plan(reviewed): <slug> at ` commit, anchored at both ends. A candidate `git merge-base --is-ancestor` refuses is dropped, and none left means full scope; a filtered range with no commit reports clean without opening a file. Any command that records `**Reviewed at:**` without itself reviewing must commit under another subject — `/esq:converge` uses `plan(converged):`, because its record covers final fix commits no review read (D-review-delta-base-is-a-reviews-own-record) — *why:* an unanchored slug let a `<slug>-fixes` record answer for `<slug>`, and a shared subject would let a re-review narrow past fixes nobody reviewed, both silently; scenario R-08 pins the three clauses with fault injections, but a new recorder is caught by nothing but this rule.
- **A plan is committed before the work it describes, never after it.** A first review with no recorded baseline reviews `<plan commit>..HEAD`, the base resolved from the plan's own `plan: <slug>` commit; so work built ahead of any plan ships by cutting a new unit from the same base, committing the plan, and replaying the built commits above it — never by planning on top of them, and never by rebasing commits already cited elsewhere (D-replay-built-change-above-plan) — *why:* a plan committed above its implementation puts that implementation below the review base, and the independent review then covers only the corrections, silently; nothing mechanical notices, because the range it reviews is well-formed.
- **`esq merge` is the only thing in esquisse that writes git history nobody authored by hand, and it never pushes.** Skills commit their own work, and since 2026-09-04 `/esq:plan` also creates one ref — `git switch -c esq/<slug>`, the act that brings a shipping unit into existence, with the plan file's own commit as the first thing on it. Those are authored writes on the current branch. Merging is the one write that combines two histories, and it lives here alone. One engine, five verbs (`begin`/`scan`/`seal`/`abort`/`land`), and both paths delegate to it: `/esq:worktree merge` drives the first four and answers every `ask` with the user, `esq merge land --plan <plan-path>` composes the same four with the derive rules answering and aborts on the first `ask`, so the unattended path is a strict subset of the attended one by construction rather than by discipline (D-one-merge-engine-in-the-cli). The `Status` and `Pri` ladders live in `cli.mjs` with the vocabularies they order — a total order over a closed set is structure, not judgment (D-cli-owns-structure-model-owns-judgment) — and `derive(ours, theirs, base)` returns either the resolved cell with the rule that resolved it or `{ask}`; nothing re-parses conflict markers downstream. **`land`'s authority is the plan header, and it reads it itself** — in this process, immediately before the first git write, never a value a caller passed in, so there is no window between the authority read and the merge and the gate cannot be bypassed by invoking the CLI directly. `**Branch:**` is the source and `**Origin:**` the destination, both through `safeRef` and both prefixed `refs/heads/<name>` so no argument can be read as a flag. **A shipping unit lands where it started** — the destination is the origin the plan recorded, never the branch the command was invoked on and never a repository default; that origin is the branch the user was standing on when `/esq:plan` created the unit (D-a-shipping-unit-lands-where-it-started). The ship-policy layer that answered this before 2026-09-04 read its authority from a declaration blob on the destination ref, so pointing the destination anywhere else would have made the gate check a branch with nothing to do with the merge; it was deleted rather than split in two, and the superseded entries in `docs/DECISIONS.md` are where that history is kept. Inheriting the attended default (`into ?? git branch --show-current`) had already broken the feature in both directions at once, and shipped because every `mergeLand` fixture ran with HEAD on the destination: from the source branch — the only state the landing's own branch gate permits — the merge refused `self` and never fired, and from a third branch it landed onto a ref that had authorized nothing. Any new caller of the engine states its destination from the authority it read, never from where it happens to be standing. **And a shipping unit lands in the checkout that holds that destination**, which is not always the one the command was invoked from: `mergeBegin` reaches its destination with `git switch`, git refuses to check one branch out twice, and in the layout `/esq:worktree` itself creates — a source branch in a linked worktree beside its origin in the main checkout — the landing was therefore impossible, refusing only after `/esq:land` had paid its verification (B-154). `landingSite(root, destination)` answers, read-only from `git worktree list --porcelain` parsed once in `worktreeRecords`, which checkout owns the destination and whether it can be merged in: `here` for every case that behaves as it always has (the destination checked out in this tree, in none at all, or a branch that does not exist — `mergeBegin`'s own switch and its own `absent` refusal still decide), `worktree` for a clean registered worktree that holds it, and `dirty` / `locked` / `gone` / `moved` / `foreign` otherwise, each carrying the real path and one `git -C '<path>' …` line that clears it. It rides on the branch verdict as `destination` so `/esq:land` can stop on an unusable one out of a verdict it already read — the tenth prerequisite, before the only step that costs minutes — and `esq merge land` resolves it **again, in its own process**, immediately before the first git write, under the same rule as the two refs: a site resolved in a preflight is a claim about a directory that has had a verification's worth of time to change. **Nothing about another checkout is taken on the registry's word** — the chosen directory is asked itself whether it reports the same common git directory, whether it is still on the intended destination, and whether it is clean, which is also what makes a stanza the plain porcelain format garbled (a path containing a newline is not representable in it) refuse rather than get merged into. The three verbs are unchanged; only their root is, and the abort restores **that** tree's branch rather than the caller's. **The merge moves and the verification does not:** `esq gate verify` stays rooted at the invoking checkout, against the source tree, and a caller that handed it the destination path would verify the destination's older code in place of the code being landed. Nothing detaches, switches, unlocks, prunes or removes a checkout the run does not own — a hand-off says what to do and where, and the `cwd` field beside `command` is that *where*, because `/esq:worktree merge` merges into whatever branch the session running it has out, so the bare line handed to a user in the source worktree reproduces the location failure it was offered for (D-a-landing-runs-where-the-destination-lives). The attended verbs stay ungated: a user typing `/esq:worktree merge` is the authority. A plan that is missing, records no `**Origin:**`, or carries a field `safeRef` rejects is **refused, never repaired** — a shaped no-op naming the field, not a sanitized ref. **Every refusal is a no-op** — it aborts the held merge, leaves HEAD where it was found, and never touches the source branch or a single commit on it — and carries the exact `/esq:worktree merge` line a human would run instead, because a long list of ways not to land plus a bare reason is how a user ends up unable to tell why. **And nothing pushes.** The blast radius is the whole argument: a local merge commit is recoverable by whoever ran the command, a push can deploy, notify or start a pipeline and is undoable from nowhere. No verdict, field or flag names one, and the promise is held by `scripts/check-nopush.sh` as a product check, which has no opt-out list because the one site that would have fired was fixed instead (D-esquisse-never-pushes).
- **Landing is `/esq:land` alone, and nothing lands on its own.** `/esq:converge` stops at *ready to land* and never calls `esq merge land`; `/esq:land` runs no finder and may write one evidence-backed backlog bookkeeping commit before calling the merge engine, which makes one merge commit or none; neither pushes, publishes or releases. Every prerequisite is a fact the CLI returns — never re-derived in prose — and a failed prerequisite stops with the command that clears it; any proved backlog closure already committed at prerequisite 7 remains, while all other failed prerequisites make no write, never a prerequisite lowered because the finding looked small — and never advice raised into one: projection freshness protects documentation rather than the merged code, so it is reported and never refused on (D-projection-freshness-is-advice-at-landing). Folding the landing back into the loop re-creates what this split removed: a clean loop as the only way to land, with nothing recording that a review covered the tree, that every plan of the unit was built or deliberately abandoned, or that the unit disposed of the rows it promised (D-landing-is-its-own-command).
- **Harness evidence is diagnostic, never a delivery gate.** `esq evidence` can report a claim's measurement status and its historical `Governs` label, but no skill reads that verdict to authorize a spawn or stop work. Relays request `model: opus` on workers; whether the host honors it is unobserved, reported without an extra probe, and never blocks delivery.
- **The runtime-eval seed grows only by addition.** Every journey is judged against one toy project; a file may be added to it, but the instructions and files the existing journeys already read are never changed — *why:* a seed edit re-scopes every journey silently, and their captures are paid evidence that cannot be re-judged against a seed they never ran on (D-the-shared-seed-grows-only-by-addition). An overlay may never restate a seed file, and `tests/journeys/journeys.test.mjs` reds if one does.
- **`docs/SPEC.md` and the ledgers are never written by `/esq:arch`, and projections are never merged by `/esq:worktree`.** Each projection has one writer; a second one makes the freshness markers lie.
- **Subagent telemetry never joins on anything but `agentId`; direct rows are keyed `(sessionId, segment)` and never pooled into the subagent tables; neither stores a description, prompt or response.** A label carries a **closed set** of fields, each validated against its own fixed pattern before storage by writer and reader both — the `esq:<command>` slug, the spawn's `requestedModel`, the declared plan slug, the `repoKey` — and widening that set is a decision taken on the record, never a convenience: `repoKey` was taken for B-121 because a machine-wide store cannot scope a missing identity without it, and `agentId` joined the read-only run-row allowlist (`RUN_ROW_KEYS`) for `--rows` because the rows a coverage rate turns on are precisely the ones with no slug to key on, and it is a harness-generated identifier **already in the store** — the key `EXCLUDED_RUNS` matches on — rather than anything a hook newly writes (D-run-row-carries-the-agent-id). What the list still refuses is the whole of what minimization was ever about: no prompt, no response, no tool input, no path, no session identity, no code content. Adding a field that carries any of those, or reading a text block in the session writer, is a regression `tests/hooks` will catch.
- **`plugin/lib` imports nothing from `plugin/scripts` except `hook-io.mjs`'s pure helpers.** Hooks load `lib` (`markdown.mjs`, `validate`); the reverse direction exists for two predicates only — the telemetry opt-out and `carriesWholeRunUsage` — so each rule a writer and the reader must agree on has one definition. Any further such rule (what counts as a run, what counts as usage) goes into `hook-io.mjs` the same way; restating it in `telemetry.mjs` drifts silently, and importing a handler into the lib, a second shared file, or a `hook-io.mjs` that grows a non-built-in dependency makes every hook load the CLI library or splits the two packages apart — whoever separates them carries `hook-io.mjs` with `lib`.
