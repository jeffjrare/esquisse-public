# B-075 — parked work in existing readers

Base: `1238e0a3bac781f310afe223063572e9715b48a5`. Scope: orientation in
status, roadmap and backlog. No new status or ledger field.

## Observed defect

On the real checkout, `./plugin/bin/esq state` returned B-001 Open and B-006,
B-085/B-087 Planned, with explicit deferral in summaries/roadmap prose. The only
local plan file was the phase-less README; historical plans are intentionally absent.
The roadmap's recorded acceptance carried useful restart conditions, but the CLI
omitted that field. Separately, source inspection found roadmap's unconditional
`Planned → in flight` rollup and status's `complete plan → candidate to close`.
These are observed reader/source defects, not a captured native model misresponse.

## Smallest selected change

Keep reason and restart condition in existing prose. Readers show them beside the
canonical status and exclude explicitly parked work from automatic restart/closure
advice. A selection can satisfy a selection condition; external prerequisites still
need evidence. Missing facts remain unspecified. Parking neither clears a shipping
obligation nor hides other work in a mixed entry/plan. Complete phases do not settle
outstanding item acceptance.

The CLI adds only `roadmap.entries[].acceptance` (existing text or null); its legacy
head, statuses and order remain unchanged. Judgment stays in the skills. There is
no parking classifier, new service, extra read in state, or new writer.

## Real-case observation

Ran state once before and once after the implementation, before ledger bookkeeping.
Compared the actual JSON: backlog, plans and legacy head were identical; removing
only acceptance from the new entries reproduced all old entries in their original
order. The new field returned each recorded acceptance below.

Applying the revised reading rules to those real facts gives this compact orientation
(maintainer interpretation, not output from a native `/esq:status` trial):

| Work | Canonical status | Reason for deferral | Restart condition from retained sources |
| --- | --- | --- | --- |
| B-001, Sheets | Open | Partner workflow not selected; historical connector dependency | Select the need and revalidate connector capability |
| B-006, Codex | Planned | Cross-host delivery not selected; historical adapter plan omitted | Select a cross-host use case and reassess current host contracts |
| B-085/B-087 | Planned | Historical plan complete; operational acceptance remains unproved | Concrete recurrence or relevant harness capability change |

None earns an automatic build, closure or connector/research run. Historical plan
completion remains attributed to recorded evidence, not a local plan we inspected.
The real mixed B-129 Done/B-079 Open entry still returns both statuses and its
acceptance; it remains valid Now work, not parked or stale by membership alone.
