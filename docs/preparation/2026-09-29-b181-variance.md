# B-181 — Variance : trois essais par bras au lieu d'un

## Protocole

Plan `2026-09-29-b181-variance-then-fix`. Les trois verdicts précédents sur B-181 reposaient
chacun sur **un** essai, et celui du 2026-09-29 ([fidélité](2026-09-29-b181-fidelity.md))
mêlait la correction, 17 versions du plugin et une mise à jour de Claude Code. Ici, chaque bras
compte trois essais, sur le même cas, le même jour et la même version de Claude Code.

**Critères de clôture** (fixés par le plan avant tout essai, repris du brief du 2026-09-29 et
du [jugement préalable](2026-09-25-b181-tamialog/judgment.md), sans changement). C1 : la valeur
de quantité est remplacée, ou le conflit est signalé. C2 : l'avis d'écart est lu dans
`QuickLogSheet`, pas dans une modale. C3 : pas de verrou SPEC ni de nouveau grill. C4 : la
maisonnée vient après Steps et avant Forecasting. C5 : la copie FR/EN est complète, avec
« powdered-formula ». C6 : une phase complète, avec build, tests landing et audit `--no-build`.
C7 : pas d'état Git inventé. Le lecteur juge, sans score de présence de mots.

**Règles fixées avant tout essai.** *Clôture* : chaque critère tient dans ≥ 2 essais sur 3 du
bras jugé. *Échec fiable* : un critère qui échoue dans ≥ 2 essais sur 3 de la référence. Seuls
ces critères reçoivent une correction (phase 2).

**Cas** : `/tmp/b181-variance-case`, reconstruit comme pour l'essai de fidélité. Les blobs Git
de `events-tracker` listés dans [inputs.json du 2026-09-25](2026-09-25-b181-tamialog/inputs.json)
viennent du commit `33e750a1`, avec **437/437 SHA-256 identiques**. Le plugin vient de
`git archive HEAD plugin` au commit `62eb89b` (47 fichiers, version 0.3.65), soit 484 fichiers
au total, sans `.git` ni lien symbolique. `plugin/skills/plan/SKILL.md` vaut `4cd1d43e…`, exactement
la source d'avant la correction retirée en `a5e1666`. `docs/plans/` ne contient que les trois
briefs : pas de `judgment.md`, pas de plan final. Les empreintes du plugin sont dans
[inputs.json](2026-09-29-b181-variance/inputs.json). Le
[prompt](2026-09-29-b181-variance/prompt.txt) est identique à l'octet près (`d17732b6…`).

**Borne annoncée avant le lancement : 3 essais, Opus / medium, 3 USD / 180 s au plus chacun,
9 USD au plus pour la phase.** Les montants sont les estimations au tarif catalogue de la CLI.

`claude-opus-5-5`, aucun refus d'outil ni erreur d'outil.

**Règle de conservation (fixée avant tout essai) : tenue.** Chaque critère visé gagne au moins un
essai (C1 +2, C5 +1, C6 +2), et aucun critère n'en perd deux (C7 −1, C2 inchangé). **La
correction est conservée** et la tâche 2.4 (retrait) ne s'applique pas.

**Règle de clôture : non tenue.** C5 et C7 tiennent dans 1 essai sur 3. **B-181 reste Open.**

- **C1** passe de 0/3 à 2/3. C'est la première fois que le défaut nommé par B-181 est tenu sur
  plusieurs essais. Dans l'essai 3, le conflit est nommé dans la disposition et pas dans
  `## Risks`, comme la correction le demande. Le critère le compte quand même, puisqu'il demande
  seulement que le conflit soit signalé.
- **C5** ne gagne qu'un essai. La perte de « en poudre » en anglais reste le cas le plus fréquent
  (2/3). C'est le critère le plus fragile.
- **C6** passe de 0/3 à 2/3. La clause sans build fonctionne dans deux essais sur trois.
- **C7 recule d'un essai.** Deux propositions affirment un HEAD détaché qu'aucune lecture n'a pu
  observer. Le même défaut apparaissait le 2026-09-25 et dans l'essai de fidélité. Il n'est pas
  visé par la correction, et la référence l'avait tenu 2/2 sur les essais livrés. Rien ne permet
  de l'attribuer à la correction plutôt qu'au bruit.
- **C2** : la lecture de la modale revient dans un essai sur trois (essai 3), comme dans l'essai
  de fidélité. C'est un échec intermittent, pas nul.
