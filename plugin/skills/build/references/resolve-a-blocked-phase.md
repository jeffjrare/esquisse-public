## Resolve a blocked phase

A phase is blocked when its last build run committed the code and passed every `(auto)` step, but found a 🐛/⚠️ defect against its own shipping unit that it could not dispose of. Its execution-log entry is headed `⏸ blocked on an open same-unit defect` and carries a `**Blocked by:**` list. Resolve it before any new phase runs. **Nothing on this path re-executes the phase** — its commits are already in the tree, and no task is implemented a second time here.

The transition is `esq plan resolve-block`, never an edit. The entry is machine-written and the fact that releases it is a ledger cell this process can read, so the flip is a CLI write that refuses rather than a header you rewrite by hand — and every refusal below leaves the plan file byte-identical, which is what makes the whole section safe to re-enter after an interruption.

1. **Ask** — `esq plan resolve-block <plan-path>`, read-only, writes nothing, safe to run twice.
   - **`refuse: true` with code `blockers-open`** → first carry out the dispositions your own evidence already settles: a named row that a commit in this unit fixed and a passing `(auto)` step verified is closed with `esq backlog set-status <B-NNN> Done --by <slug> --resolution "<the fix, in <hash>>"`, committed once, then ask again. A row still open after that is a real decision — fix it now, or accept it unfixed — and STOP there as an authority stop: one NEEDS YOU line per row, with `/esq:work <B-NNN>` to fix it and `/esq:backlog <B-NNN> dropped` to accept it, and `→ Next` repeating the first. Never drop or re-file a row yourself to get past the gate.
   - **`refuse: true` with any other code** → STOP and report its `reason` verbatim. `already-resolved`, `blocker-missing` and `malformed-entry` each name a state no rerun of this command changes.
   - **`refuse: false`** → continue. `owed` names the `(auto)` commands git cannot prove still green; `verify.unresolved` names the steps whose command cannot be recovered from their own prose.
2. **Run what is owed, and nothing else.** Each command in `owed` exactly once, plus each entry in `verify.unresolved` in full. Everything not in either list is evidence already bought — the phase proved it on a tree git can still see, and re-running it buys a fact already in hand. Judge each result against its own `step` text and never against exit 0.
   - **Any red** → the phase stays blocked. Report the failing step in one line and stop; do not confirm. A red command is one you leave out of the payload below, and leaving it out is exactly what holds the pause.
3. **Confirm** — `esq plan resolve-block <plan-path> --confirm '<json>'`. The payload is `{"phase": N}`, plus — when anything ran — `verified`, `{"at": "<the full 40-hex commit the reruns were judged on>", "commands": [<every command judged PASS>]}`, and `verification`, one `(auto) <command> — <result>` line per rerun. The CLI re-derives the unit, the dispositions and the freshness itself rather than trusting step 1's answer, and refuses if a command in `owed` is missing from `verified.commands`. When the entry also lists `**Manual verification outstanding:**` and you have already observed those steps, pass `manual` in this same payload and the entry resolves straight to completed — one write instead of two.
4. **Read what it wrote.** The entry now carries `**Blocked by (resolved):**` — each id, its `Done`/`Dropped` disposition and the reason recorded with it — and its `status` is one of two:
   - **`completed`** → the phase is done. Say so in one line and **continue straight into the next phase** in this same session: resolving a block implements no task and writes no code, so on the same grounds as settling a `⏸` pause you observed yourself, it does not consume this invocation's phase budget.
   - **`paused`** → the phase also owed `(manual)` steps, so it stays paused under `⏸ awaiting manual verification`. Go to "Resolve a paused phase" above and settle it there, in this same run.
     In the plugin that section, and the "Observe the `(manual)` steps" procedure it runs, are both in `${CLAUDE_SKILL_DIR}/references/manual-verification.md`: you MUST load it before you settle the pause, and a run that resolves one never self-certifies the steps instead.
5. **Commit the plan file alone**, chained in one call: `git add <plan-file-path> && git commit -m "plan(<slug>): resolve phase N's blocked pause"`.

**Interrupted anywhere in here, start again at step 1.** The disposition is already in the ledger, the read call is idempotent, and nothing before step 3 writes a byte; step 3 is one atomic write, and an entry it has already resolved comes back `already-resolved` rather than being written twice. Re-entering costs only the reruns step 2 still owes — never a task, and never a row filed twice.
