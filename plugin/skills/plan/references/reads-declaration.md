## Declaring what an `(auto)` command reads

Loaded only when a step of this plan will carry a `(reads)` declaration. A plan that
writes none never reads this file, and is complete and correct without it — the absence
of a declaration is how every plan already written is judged.

- **A step may declare what its command reads, and the declaration is a promise, not a guess.** After the property sentence, an `(auto)` step may carry `` `(reads)` `` and then the repository paths that command reads, as inline-code spans separated by commas or `and`: `` - `(auto)` `node --test tests/cli/merge.test.mjs` — the merge suite is green `(reads)` `plugin/bin/`, `plugin/lib/`, `plugin/scripts/`, `tests/cli/merge.test.mjs` ``. `esq gate verify` then judges *that one command's* freshness against those paths alone, so a landing stops re-buying a suite the shipping unit never touched, which `D-a-step-declares-what-it-reads` measured on one shipped unit. **The declaration is optional and its absence is the default:** an `(auto)` step with no declaration is judged exactly as it always was, which is every plan already written. **Declare nothing unless reading settles it.** Resolve the command's inputs the same way you resolved what it *selects* — read the file it runs, the modules it imports, the fixtures and configuration it opens, the scripts it shells out to — and where any of that cannot be settled by reading, write no declaration: an undeclared command costs minutes, an under-declared one costs the regression that lands unproven. **Never declare one for a whole-repo guard.** A whole-repo suite, an audit script, a lint over the tree — anything whose inputs are "most of the repository" — gets no declaration, because the only honest one would name the repository and the only short one would be false. **The declaration names what the command reads, never what this phase changed.** They are different sets, and writing the second is the way a declaration goes wrong: a suite reads the module under test *and* every helper, fixture and config it reaches, whichever phase last touched them. **A declaration the gate cannot trust changes nothing:** `esq gate verify` ignores it whole and runs the command when it names no path, carries prose, names an absolute path, a `..` segment or a glob, or fails to cover a path the command itself names — and matching is by whole path segment, so `plugin/lib` covers `plugin/lib/cli.mjs` and never `plugin/library.mjs`. **What the gate checks is shape, never completeness.** It reads the declaration's syntax and the paths the command names out loud, and refuses a command form it cannot decompose at all — it can see none of a suite's imports, a runner's configuration or a binary the command spawns. So a declaration it accepted is one it could not refuse, never one it verified: completeness is yours, which is why one is withheld wherever reading does not settle the command's inputs.
